## 模块划分（对应五大功能）

| 模块 | 职责 | Eino 编排形态 |
|---|---|---|
| **简历解析** | 解析 PDF/DOCX → 抽取技能/项目/经验 → 结构化能力画像 | Workflow（线性：解析→抽取→结构化） |
| **查漏补缺** | 画像 vs AI 工程师能力模型，输出强项/薄弱/缺失 + 学习路径 | Graph（对比→检索资料→生成计划） |
| **笔试生成** | 按弱点/岗位生成题目（选择/编程/系统设计），判分、解析 | Graph（选题→生成→校验→组卷） |
| **模拟面试** | 多轮问答 + 追问 + 评分（技术面/行为面），HITL 可选 | Agent（LLM 主导循环，带状态记忆） |
| **技术雷达** | MCP 联网检索近期 AI 动态，摘要 + 关联到你的薄弱点 | Workflow（检索→去重→摘要→排序） |

## 技术选型理由

- **Eino 而非裸 Go**：内置 Graph/Workflow/Chain 三种编排、状态管理、checkpoint（HITL 中断恢复靠它）、callback 可观测。对标 LangGraph。
- **Ollama 优先做模型后端**：本地、免 API key、Go 原生亲和（Ollama 本身就是 Go）。也支持 OpenAI 兼容接口切换。
- **SQLite + 向量检索做记忆**：单文件部署、够用；用户画像 + 错题 + 面试记录持久化，跨会话"越用越懂你"。
- **MCP 接工具**：技术雷达的联网检索、题库检索都通过 MCP 标准化接入，后续可插拔。

## 数据流示例（查漏补缺）

```
用户请求 → 读取能力画像(记忆) → 加载 AI 工程师能力模型
   → Graph 节点1: 逐项对比打分
   → Graph 节点2: 检索薄弱项学习资料(RAG)
   → Graph 节点3: LLM 生成个性化补齐计划
   → 写回记忆(更新弱点权重) → 返回前端
```

## 部署形态

- 开发期：前端 Vite dev server + 后端单二进制（或 mock）
- 生产：前端静态资源 + Go 单二进制，SQLite 文件挂载，Ollama 作为 sidecar
